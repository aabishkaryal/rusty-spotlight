# Council round 1 · Astra · 21 November 2026

**Build a resident macOS command launcher with an AppKit panel, a Rust search engine and a small protocol for trusted local scripts.** Optimize the time from a user's first keystroke to the *right action*. A panel can paint in 15 ms and still feel slow if the first match moves under Return. My switch criterion is a week using it as the primary launcher, including after sleep, on a second display and while typing in another language.

**Evidence convention.** Dated releases, upstream descriptions, measurements and API statements attributed to linked sources are findings checked today by web search or by reading upstream metadata/source. The release ledger gives the lookup method. Design choices, expected costs, schedules and numerical targets are my engineering judgments. Uncited implementation details are engineering knowledge from memory and should be validated in the proposed spikes. I did not build or time these products locally. Project activity measures are observations, not evidence of user satisfaction or explanations for a maintainer leaving.

## 2. UI decision

Choose **objc2 + AppKit**. Use a real editable search field, reusable view-based NSTableView rows, NSCollectionView for grids, native split views, selectable detail text and ordinary form controls. Cache the model and a small panel while hidden. Expose semantic theme tokens (appearance, accent, density, type size), allow Reduce Transparency and Increase Contrast to win. Use NSVisualEffectView with an opaque fallback; downsample icons to display size. This gives every extension the host's keyboard behavior, selection, IME candidate positioning and accessibility plumbing. Custom cells still require accessible names, roles and actions. The price is main-thread ownership, Objective-C lifetime boundaries and another renderer if Linux ships. [objc2](https://docs.rs/objc2/) · [AppKit](https://developer.apple.com/documentation/appkit) · [table reuse](https://developer.apple.com/documentation/appkit/nstableview)

The following are **relative engineering costs**, not cross-framework measurements. A warm hidden window and a cold executable answer different questions. Every GPU or web option needs icon decode/upload limits, bounded visible rows and a verified native panel bridge. No comparable cold/hot/frame/RAM benchmark across these exact versions was found.

## 3. macOS integration contract

- **Show, type, dismiss.** Construct a borderless floating NSPanel with the nonactivating style at initialization. Permit it to become key, keep it from becoming main, bring it forward and put the field editor first in the responder chain on the AppKit thread. The caller can remain the active application while the panel owns keyboard input. Do not activate the agent every time. A text-first panel must accept typing on summon without a click; test the field's needsPanelToBecomeKey and panel's becomesKeyOnlyIfNeeded together. Dismiss via orderOut on Escape, second hotkey or genuine outside interaction; IME candidate windows and menus must survive. Snapshot the frontmost app on show. Normally ordering out suffices; explicitly restore a live previous app only when activation was actually transferred and the user hasn't switched elsewhere. Running an app-launch action deliberately hands focus to the target. [NSPanel](https://developer.apple.com/documentation/appkit/nspanel) · [key behavior](https://developer.apple.com/documentation/appkit/nspanel/becomeskeyonlyifneeded)
- **Spaces and displays.** Start with floating level and canJoinAllApplications for eligible foreign fullscreen/Stage Manager spaces. Test canJoinAllSpaces with that policy; alternatively moveToActiveSpace for a panel attached to a single Space. Avoid combining contradictory Space policies or mutually exclusive primary/auxiliary/all-applications roles. Compare fullScreenAuxiliary on supported versions. Position in the invoking display's visible frame (default pointer display); test separate Spaces per display, menu bar/autohide Dock, display removal, Stage Manager and fullscreen transitions. No screen-saver-level workaround or private WindowServer API. [Apple’s overlay guidance](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/canjoinallapplications)
- **Hotkey.** Register one chord using global-hotkey on the main event loop; on macOS use the Carbon RegisterEventHotKey path. No reason to inspect all keyboard events. Handle registration failure, repeats, wake, layout changes, and rollback when rebinding fails. Default Option-Space if free. To replace Command-Space, guide the user through Keyboard → Keyboard Shortcuts → Spotlight and check input-source conflicts, then test registration. Never silently modify system defaults. CGEventTap has broader consent, secure-input and timeout implications; reserve it for a future feature that genuinely needs observation. [global-hotkey](https://github.com/tauri-apps/global-hotkey) · [Spotlight shortcuts](https://support.apple.com/guide/mac-help/spotlight-keyboard-shortcuts-mh26783/mac)
- **Agent and login.** LSUIElement in the signed bundle, optional NSStatusItem with Settings, Show, Pause history and Quit. Keep Settings an ordinary focusable window. Register SMAppService.mainApp only when login launch is enabled; surface enabled/requiresApproval/notRegistered and link to Login Items if needed. Reuse the same bundle identity across updates. [LSUIElement](https://developer.apple.com/documentation/bundleresources/information-property-list/lsuielement) · [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)
- **Apps.** Show a cached catalog immediately. Enumerate /Applications, /System/Applications and ~/Applications with package boundaries, including subfolders but skipping nested helper bundles. Augment asynchronously with Spotlight application-bundle results for user-selected/nonstandard volumes. Use public NSWorkspace/LaunchServices for resolving/opening the selected bundle URL. Avoid private LaunchServices database dumps or assuming bundle ID uniquely identifies an install. Preserve separate URLs for side-by-side builds, prefer local applications, skip unavailable volumes, honor localized display names, verify existence at launch. Fetch NSWorkspace icons lazily; cache scaled bitmaps by URL, bundle modification/version and scale; bound decoded memory. [NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace) · [Launch Services](https://developer.apple.com/documentation/coreservices/launch_services)
- **Files.** Query the existing Spotlight index via NSMetadataQuery on a thread/run loop or operation queue that can receive notifications. Scope to selected folders/home, use parameterized predicates, gather in batches, stop old queries and drop their callbacks. Search names first; make contents explicit. Snapshot bounded results under controlled updates; never enumerate a huge live result proxy on the UI thread. Use mdfind as a diagnostic baseline rather than forking it on each keypress. Explain excluded paths, offline volumes and indexing delay. No second home-directory index. FSEvents reports changes, not durable search documents: an independent index requires initial scans, persisted event IDs, rescan on drops, rename and mount handling, permissions and deletion semantics. Revisit only for explicitly opted-in unindexed roots. [NSMetadataQuery](https://developer.apple.com/documentation/foundation/nsmetadataquery) · [FSEvents guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/)
- **Permissions.** Ordinary app launch, local ranking, a registered chord and basic metadata search should work with all optional permissions denied. Do not request Full Disk Access as onboarding; file visibility depends on source scope and macOS privacy controls. AX trust is feature-specific for inspecting/moving other apps’ windows or simulating paste; check AXIsProcessTrustedWithOptions on user action. Apple Events automation is a separate per-target consent path for AppleScript-driven integrations; defer and explain target. Screen Recording is for capturing pixels, unnecessary for moving a window. Input Monitoring is distinct from shortcut registration. Test denied, revoked and re-granted permissions on a signed build. [AX trust](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions) · [Mac privacy settings](https://support.apple.com/guide/mac-help/change-privacy-security-settings-on-mac-mchl211c911f/mac)
- **Clipboard.** Off by default. On opt-in observe general pasteboard changeCount with a coalesced low-frequency timer; read at most once per changed count, text only, pause on lock/sleep. Sampling can miss rapid consecutive copies. Honor accessBehavior and macOS paste prompts; disable collection cleanly if background reads are denied. Skip concealed, transient, autogenerated and user-excluded sources where identifiable; source attribution is best effort. Never promise secret detection. Default session-only, explicit persistence with short TTL and Clear All; keep contents out of logs/backups where feasible. Selecting an entry copies it; simulated paste is a separate AX-enabled action. [NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard) · [concealed pasteboard types](https://nspasteboard.org/)
- **Window commands.** Later, get focused window via AXUIElement, check settable position/size, map screen coordinates correctly across varying origins and scales, set and read back with bounded timeout off the main thread. Expect minimum sizes, refused writes, transient sheets and fullscreen windows. Start with left/right/maximize/restore and preserve the original rect per window. [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement)
- **Distribution.** Direct Developer ID release, hardened runtime, stable bundle ID, sign nested helpers/frameworks inside out, timestamp, submit via notarytool, staple and verify Gatekeeper on a clean machine. Use Sparkle **2.10.1, Oct 25** with signed archives and HTTPS appcast; separate EdDSA update key from Apple signing credentials, verify a real upgrade and bad-signature rejection. Prefer this to a hand-written swapper or shipping a cross-platform updater solely for one OS. A narrower sandboxed app with user-picked roots is plausible; broad AX automation, arbitrary external scripts, downloaded functionality and self-updates make the proposed product a poor Mac App Store fit. Review 2.4.5 and 2.5.2 before promising a store edition. [Notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) · [Sparkle](https://sparkle-project.org/documentation/) · [Sparkle releases](https://github.com/sparkle-project/Sparkle/releases) · [review rules](https://developer.apple.com/app-store/review/guidelines/)

## 4. Retrieval, ranking and a definition of fast

**Choose frizbee for scoring a resident catalog.** Its SIMD Smith–Waterman implementation offers typo matching and score-only evaluation. Its author reports roughly 4× nucleo on the included benchmark with typos disabled; the published machine was a Ryzen 9950X3D on Linux. The reported Unicode speedup depends on representation, corpus and settings. Neither ratio predicts end-to-end latency on Apple Silicon. It does no Unicode normalization for you. Nucleo is the fallback and the benchmark control: its parallel, incremental worker and snapshot interface are a better ready-made engine for streaming a single huge corpus. Here we already need cancellation and merging across heterogeneous providers. Skim is a complete finder and currently uses frizbee; the old fuzzy-matcher crate is a different dependency. sublime_fuzzy is a simple boundary-aware baseline. The 2020 release dates of the latter two alone do not establish defects; neither supplies a reason to choose it over the measured candidates. [frizbee](https://github.com/saghen/frizbee) · [benchmark environment/data](https://github.com/saghen/frizbee/blob/main/BENCHMARKS.md) · [nucleo](https://github.com/helix-editor/nucleo) · [skim](https://github.com/skim-rs/skim) · [sublime_fuzzy](https://docs.rs/sublime_fuzzy/)

1. At ingestion, retain original labels/URLs, stable IDs and localized aliases. Precompute normalized case-folded keys, token starts, camel-case initials and word acronyms. Maintain a mapping to original grapheme clusters for highlight ranges, including the conversion to AppKit UTF-16 ranges. Keep diacritic folding an alternate match; native spelling wins. A Chinese app can expose full pinyin and initials as optional lower-priority aliases. Prefer bundled explicit readings for ambiguous names; don't transliterate all scripts indiscriminately. Test Japanese kana, decomposed accents, Arabic/Hebrew mixed with Latin and emoji ZWJ sequences.
2. Route explicit scopes/keywords before fuzzy search. Order exact user aliases, exact titles, token prefixes and acronyms ahead of subsequences, with bounded learned preference within a tier. For short inputs favor precision. Only try one-error matches on queries of at least four graphemes when strong matches are scarce. A fallback alternate keyboard-layout interpretation should be opt-in, derived from active/user-selected layouts, scored below literal matches, and never applied to paths, URLs or IME marked text. Keep the characters the user entered visible.
3. Learn only on confirmed actions. Store a decayed count per item and per normalized query–item pair. On use, multiply the previous count by 2 raised to minus elapsed days divided by 14, then add one. At ranking time decay to now, use log1p and a cap. Give a repeated query–item pair greater weight than global popularity. Explicit aliases always win. Persist aggregate counts and timestamps; allow reset/disable. A history of every raw query is unnecessary.
4. Increment a generation on every edit. Score local entries immediately, take top K with a bounded heap, compute highlights only for painted rows. Refine previous candidates only when the transformation preserves the match set; backspace, typo fallback, mode changes or new provider batches can expand it. Cancel obsolete work cooperatively and discard all stale generations at the merge *and* render boundaries. Start file queries after a short trailing delay (~50 ms); never debounce the first local paint. Batch provider updates at most once per frame. Deduplicate by canonical action/target, reserve a section for slower files and preserve the selected ID once the user navigates. Bind Return to the displayed ID and generation, never to a later row number.
5. SQLite in WAL mode for the catalog cache, frecency, aliases and migrations; read from an immutable in-memory snapshot in the hot path. SQLite FTS5 fits large opted-in text collections such as persistent clipboard/bookmarks; use parameterized MATCH construction and prefix/token queries. An fst fits a large immutable lexicon needing prefix/automaton intersection, poorly fits live mutable ranked items. Tantivy earns its segment, compaction and schema costs only for an owned full-text corpus requiring fields, BM25 or facets. Spotlight already indexes files. [FTS5](https://sqlite.org/fts5.html) · [fst](https://docs.rs/fst/) · [Tantivy](https://github.com/quickwit-oss/tantivy)

**Published baseline.** Asyar's October 4 M4 Max/macOS 27.0.1 black-box run (15 summons per product) reports Asyar 0.1.1-49 vs Raycast 2.6.2.0: median **13.9 vs 22.2 ms**, p95 **17.3 vs 32.0 ms**, cold usable **585 vs 2,129 ms**, idle all-process footprint **419.2 vs 451.5 MB**. Its keystroke-to-painted-results cells are empty. Window detection is a proxy for photons and a sample of 15 is inadequate for a dependable tail. Separately, one author's M2 Pro/Sonoma observation puts **Alfred 5 around 200 ms / 50 MB** and **Raycast 1.70 around 180 ms / 70 MB** to command input / resident memory. Different versions, endpoints and memory accounting make these unsuitable for a combined league table. I found no reproducible head-to-head for this week's Alfred 6.0.2 and Raycast 2.13. [Asyar table and harness](https://github.com/Xoshbin/asyar#benchmarks) · [measurement procedure](https://github.com/Xoshbin/asyar/tree/main/benchmarks) · [Alfred observation](https://zenn.dev/yahat/articles/d08149135ecfd6?locale=en)

## 5. Extensions: ship a protocol before a runtime

**v1: explicitly installed, trusted local executables, out of process, invoked by keyword or action.** Read static manifests at startup, never run discovery scripts on summon. Offer a one-shot JSON list/result mode for shell authors and a versioned newline-framed JSON-RPC 2.0 session for interactive commands. The latter can remain warm briefly *after explicit invocation*. Use stdin/stdout for data, stderr for bounded diagnostics, explicit deadlines, bounded messages and result counts, cancellation IDs, crash backoff and whole-child-group cleanup. Don't invoke a shell to interpolate a query. Default local extension actions: return rows, render plain detail, copy a value, open a validated URL, or ask the host to run an explicitly chosen command. The host owns keyboard input, item IDs, theme, accessibility and navigation. Version the schema; lists and detail first, forms/grids when two real integrations need them. [Alfred precedent](https://www.alfredapp.com/help/workflows/inputs/script-filter/json/) · [JSON-RPC](https://www.jsonrpc.org/specification) · [Windows process precedent](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/extensibility-overview)

| Option | Developer experience, startup, UI and trust decision |
|---|---|
| Stdio processes | Any language, executable fixtures and easy debugging. Fork and interpreter startup cost is paid only when selected. Crashes and hangs can be contained. **A same-user child can use its own filesystem/network APIs**; manifests restrict host-brokered operations only. Treat installation as running a local program. No automatic updates or public one-click script marketplace. Albert native/Python plugins, Flow external plugins and Alfred script filters are distinct designs, not interchangeable wire protocols. |
| Wasmtime components + WIT | Best subsequent boundary for downloadable, untrusted compute. A small typed host world can grant narrow, revocable host calls. No ambient filesystem, sockets or inherited environment by default; validate host paths, cap memory/output, fuel/epoch interruption and request deadlines. Put runtime in a disposable worker, cache trusted compilation products by version/target, measure compile/instantiate and code-signing/JIT entitlements on a clean Mac. WIT bindings increase author/toolchain burden; UI schema still needed. Extism provides a convenient PDK ecosystem and host calls but has its own plugin ABI. Pick WIT to own a typed long-lived interface; don't ship two WASM contracts. [component model](https://component-model.bytecodealliance.org/) · [Wasmtime security](https://docs.wasmtime.dev/security.html) · [Extism](https://extism.org/docs/overview/) |
| Embedded Lua/mlua, Rhai or Rune | Lua is small and familiar to editor authors; restrict standard libraries, native modules, host calls and execution budget. Rhai is a natural Rust embed for bounded expressions; Rune offers a richer language but a smaller pool of authors. All can describe host-rendered forms; none gives native UI or process isolation by itself. Skip a private scripting language until scripts prove a concrete startup bottleneck. [mlua](https://github.com/mlua-rs/mlua) · [Rhai](https://rhai.rs/) · [Rune](https://github.com/rune-rs/rune) |
| Deno/V8, QuickJS, Boa | Deno offers web/JS tooling and permission concepts; embedding deno_core alone does not confer the Deno CLI's policy. V8 startup, snapshots, JIT signing and dependency updates are substantial costs. QuickJS/Boa avoid much of that runtime machinery but require module loading, timers, fetch and Node compatibility work. JS alone buys neither npm compatibility nor React UI. [deno_core](https://github.com/denoland/deno_core) · [QuickJS binding](https://github.com/DelSkayn/rquickjs) · [Boa](https://github.com/boa-dev/boa) |
| Native dylibs via abi_stable | Low dispatch overhead after load; high compiler/platform packaging cost, signing/library-validation friction and full host memory access. ABI stability addresses layout/versioning, not trust or crash isolation. No third-party dylib path. [abi_stable](https://docs.rs/abi_stable/) |
| Raycast compatibility | Attractive only if the user's must-have extensions already exist there. Reimplement documented host APIs and a React renderer translating reconciler mutations/events into host view updates; React is author syntax, not a requirement for a browser. Run a separate Node worker for Node built-ins and npm semantics. Deno adds compatibility testing, Bun adds another runtime and potential native-module differences. Support storage, preferences, navigation stack, actions, images, OAuth, clipboard and lifecycle, then test representative extensions including failures. Node subprocesses run with substantial user authority. Vicinae's Node manager plus tested subset, Gauntlet's Deno reconciler and Flare's sidecar show three real costs. [Vicinae](https://www.vicinae.com/) · [Gauntlet implementation](https://github.com/project-gauntlet/gauntlet) · [Flare author](https://byteatatime.dev/posts/recreating-raycast) |

**Distribution and licensing.** Ship bundled first-party providers and an explicit local manifest importer. Before a directory/store, design immutable versions with digests, verified publisher identity, source/provenance, review, revocation and rollback, clear capability diffs and uninstall/data deletion. For compatibility, Raycast's public extensions repo carries MIT and its publishing guide specifies MIT; preserve notices and check each dependency, binary, artwork and service separately. This does not establish rights to Raycast’s runtime, brand, proprietary assets, private services or bulk Store redistribution. Start any later trial with user-supplied source, independently implemented API behavior and a named compatibility matrix. Gate a public distribution service on review of applicable terms and actual author demand. [repo license](https://github.com/raycast/extensions/blob/main/LICENSE) · [publishing guide](https://developers.raycast.com/basics/prepare-an-extension-for-store) · [terms](https://www.raycast.com/terms-of-service)

## 7. Cross-platform boundary

Ship arm64 macOS first. Share ranked item/action IDs, search and usage models, view descriptions, protocol and test fixtures. Keep main-loop, panel, hotkeys, icons, file identity, opening URLs, AX and packaging behind feature-specific adapters, not a lowest-common-denominator windowing framework. Expose capability discovery to extensions; disabled actions should explain missing platform support. Linux later: a GTK shell, layer-shell on supporting Wayland compositors, portal/compositor-assigned global shortcuts where available, normal-window fallback elsewhere; X11 has different focus and key-grab rules. Windows later: native surface, RegisterHotKey, per-monitor DPI, Windows Search/Shell links and UI Automation. Each needs its own input/IME/accessibility and installer QA. A shared search engine is a credible commitment; equivalent platform behavior is a separate product milestone. [Wayland layer shell](https://wayland.app/protocols/wlr-layer-shell-unstable-v1) · [global shortcuts portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html) · [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)

## 8. Workspace, execution and measurement

Start with one resident, single-instance app process. Keep search and paint together to avoid IPC on every keystroke. A separate always-on daemon adds resurrection, duplicate catalog and version-skew problems without improving warm summon. Start a subprocess only for an invoked extension; external app crashes must leave the launcher usable. Proposed workspace boundaries:

| Crate | Owns |
|---|---|
| launcher-core | Pure item/action identity, query parser, scoring, merge/selection rules, frecency and deterministic tests; no OS, DB or runtime types in its interface. |
| launcher-macos | Executable, AppKit lifecycle, panels, hotkey, workspace/metadata/pasteboard/login adapters; reviewed unsafe FFI confined here. |
| launcher-store | SQLite migrations, catalog snapshot load/save, aggregate usage and optional history policy. |
| launcher-protocol | Versioned request/result/view types, limits and compatibility fixtures shared by the host and CLI. |
| launcher-cli | Small client for show, toggle, search and listing commands. Plugin supervisor and built-in providers begin as host modules; split into crates only with a second consumer. |

AppKit objects live on the main thread. Send owned IDs, strings and bounded immutable batches across queues. One search worker handles latest-query-wins, a serialized DB writer commits usage asynchronously, a bounded background executor handles I/O, timeouts and subprocesses; no nested runtime or unbounded task per key. Keep an NSMetadataQuery owner alive on its designated notification queue. Use atomic snapshot replacement after a successful refresh and transactional schema migrations. SQLite under Application Support, disposable icons under Caches, user-editable versioned TOML for shortcuts, aliases and provider settings. Validate and atomically replace config; retain last good snapshot after malformed edits. Secrets for future integrations go in Keychain. Keep clip payload storage separate so history can be purged without losing ranking.

CLI talks over a user-only Unix socket in a private directory, authenticates peer UID and negotiates protocol version. Recovery from stale socket must distinguish a live owner from a crashed one. Cold CLI activation launches the registered app, then retries a bounded handshake. An optional URL scheme may show a query with escaped input; forbid silent command execution, arbitrary paths or script installation from links. No listener on TCP, no raw queries, file paths, clipboard data or keystrokes in telemetry. Local opt-in diagnostic export with counts/timings and an inspectable redacted payload. Signed releases can use symbolicated crash reports submitted by the user.

**Regression harness.** Pin Rust 1.100, the SDK, dependency lockfile and a release optimization profile. Ordinary CI runs seeded catalogs of 1k/10k/100k, cold and incremental query sequences, ranking goldens, grapheme range tests, cancellation races, protocol fuzzing, corrupt DB migrations and a child that hangs/crashes/emits oversized messages. Benchmark matching separately from ranking, allocation, image decode and first paint. Record top-1, reciprocal rank, moves after navigation and time to execute the correct action. A faster wrong match fails.

Use a **dedicated physical Mac with a logged-in graphical session** nightly: fixed OS build, power mode, refresh rate, corpus, display configuration and history setting. Signpost hotkey receipt, order-front, field-ready, local results and draw submission. Pair those with an external event injector and window observer; calibrate actual frame visibility and painted results with optical/high-frame-rate footage or timestamped screen capture. A window existing in the window list is insufficient. Send a sentinel character immediately and verify it appears in the field. Measure actual user-visible keystroke-to-correct-row on a fixed contrasting fixture. Use screen/AX permissions for the harness only. Sample ≥1,000 warm summons, ≥100 fresh-process launches across runs, and report post-reboot/first-run separately from warm disk cache. Run competitors one at a time with the same chord, fixtures and measurement endpoints; record their versions, index state and enabled extensions. Record all-process physical footprint, wakeups, idle writes, compressed download and expanded signed size. Use virtualized CI for correctness; gate hardware on persistent regressions (>10% and >2 ms across three runs) and the absolute budgets above. Publish distributions plus raw methodology, not just medians. [Asyar black-box harness](https://github.com/Xoshbin/asyar/tree/main/benchmarks) · [Apple signposts](https://developer.apple.com/documentation/os/ossignposter)

## 10. Milestones for one developer

Assume roughly full-time work, one Apple Silicon reference device and one developer making product/release decisions. Coding agents in a future implementation can prepare fixtures, adapters and test harnesses independently; allow human time for focus, accessibility, permission UX and real switching. Estimates are elapsed weeks, not promises.

| Milestone | Exit criteria |
|---|---|
| Weeks 1–2 · technical go/no-go | Run the spikes above; signed panel with reliable first character, measured competitor baseline, representative query corpus, written failures and a chosen matcher. If panel or typing fails, keep the milestone open. |
| Weeks 3–4 · replace app launch | Resident app, shortcuts, aliases, catalog, ranked actions, settings, local diagnostics and CLI show/toggle. Five working days using it as the default; meet warm-open/typing and stability gates. |
| Weeks 5–6 · daily workflows | Spotlight file scope, calculator/units, quicklinks, optional text clipboard, one-shot scripts, import personal aliases. Execute at least 27 of the top 30 real actions without falling back; every permission can be declined independently. |
| Weeks 7–8 · private beta | Native detail UI, protocol validation, signed update, revocation/error paths, migration and profile/TTL controls. Three external Mac users complete install → daily use → upgrade; one VoiceOver user can launch an app and open a file. |
| Weeks 9–10 · v1 | Seven consecutive daily-driver days, 1,000-summon suite passing, zero known wrong-target actions or clipboard leakage in fixtures, physical-machine latency/energy report, clean install/uninstall and rollback rehearsal. Cut optional features before moving a quality gate. |
| After v1 | Ship the most-requested named workflow. Consider WIT workers only after two independently authored extensions need managed distribution; consider another OS only with a committed daily tester and device. |

## Questions for the developer

| Decision | Working default |
|---|---|
| Which daily actions require Raycast, Alfred or Spotlight today? | Obtain a ranked top 30 and five actual extensions/workflows. Assume launch, open/reveal, calculate, clipboard recall and scripts dominate until measured. |
| Is replacing Command-Space essential? Which display should open? | Configurable, offer Option-Space first, support manual Spotlight rebinding; show on pointer display. |
| Minimum hardware, OS and languages? | arm64/macOS 27 for first release; include 60 Hz and 120 Hz evidence where available. Include Japanese, Chinese and mixed RTL from week one. Older OS/Intel require explicit demand. |
| Is the primary customer a script author or an extension-store consumer? | Local power user willing to install a trusted script. A store-first requirement would reopen the runtime and schedule decisions. |
| Is direct distribution acceptable? | Yes; assume Developer ID membership and a stable signing identity before private beta. |
| Which clipboard promise is acceptable? | Explicit opt-in, text only, session-only by default and a one-action pause/clear. Persistent history requires an explicit retention choice. |
| Is the goal system-wide file-content search or targeted filenames? | Filename-first over Spotlight, scoped content search later; no home crawl or Full Disk Access requirement. |
| What counts as winning on speed? | Better same-machine warm tail plus fewer keystrokes and fewer ranking errors. A microbenchmark or “native” label alone does not qualify. |
| How much time and ongoing maintenance are available? | Ten full-time weeks for a direct-download v1 plus ongoing OS regression testing. If part-time, retain gates and extend calendar time. |
