# Council round 2 · Grok · critique

Date: 2026-11-21. Attacking the drafts in `docs/REQUIREMENTS.md` and `docs/PLAN.md`. Round-1 sources: `docs/council/round1-grok.md`, `docs/council/round1-astra.md`. No code was written.

Claims marked **[searched 2026-11-21]** were checked on the web today. Everything else is from the two drafts and the two reports.

## 1. Errors

**E1. must-fix. D7 is not what the plan builds, and it is not unanimous.** D7 says one SQLite file for catalog, usage, clipboard and snippets, dissent "None". PLAN §2.3 puts clipboard history in a second SQLite file so a purge does not take ranking with it. That split is Astra's (§8: "Keep clip payload storage separate"). Round-1 Grok wanted one file. The decision table recorded one side and the plan implemented the other.

**E2. must-fix. D1's fallback and S1's fallback are different decisions.** D1 names GPUI as the fallback "only if AppKit fails a budget for a reason that is AppKit's fault." S1's failure path is a thin Swift shell, which is what round-1 Grok specified, with an explicit "Not GPUI". Claude's dissent was withdrawn in D1 and then restored as the escape hatch. M0's exit note ("AppKit via objc2 stays or the Swift-shell escape hatch") follows S1, so the decision table is the stale one.

**E3. must-fix. D11 misstates the compromise it claims to record.** The cell says section 6.3 is Astra's privacy rules and only the milestone placement is Grok's. Astra's rule was session-only by default, persistence as an explicit extra choice. NFR-32 and Q8 default to persistent storage with a 7-day TTL. That is Grok's retention, not Astra's.

**E4. must-fix. "What none of them offers" ignores the native incumbent.** §1 says nobody opens in one frame and idles under 80 MB. The only memory numbers in the drafts are Raycast 2 and Asyar, both web-view stacks. Alfred is the Cocoa launcher people already keep, and neither report established its RSS. Astra refused to put a secondary Alfred figure in the league table. The product sentence is ahead of the evidence.

**E5. must-fix. The Asyar bench is not third-party.** Requirements sources call [R2] "third-party, 15 runs". Both reports describe it as Asyar's own harness, one machine, 15 summons, 2026-10-04. Not re-fetched today. Treating a vendor self-measurement as an independent reference is how NFR-1's p95 (25 ms) ended up tighter than the only same-machine Raycast p95 in the reports (32.0 ms) without new data.

**E6. should-fix. PLAN §2.4 overstates agreement, and the level it starts from is the one a DTS reply says cannot cover fullscreen.** Grok's mask was `CanJoinAllSpaces | FullScreenAuxiliary | Stationary | IgnoresCycle` at floating level. Astra starts from `canJoinAllApplications` and tells you not to mix roles. The plan calls these the same recipe. **[searched]** Apple's collection-behavior page says `primary`, `auxiliary` and `canJoinAllApplications` are mutually exclusive. **[searched]** A DTS reply on forums thread 826308 says `.floating` and `.statusBar` both sit below fullscreen content, and the sample that does cover fullscreen uses `.screenSaver` plus a combination the docs call mutually exclusive. "Raise only if a fullscreen Space covers it" is an untested hope, not a converged recipe.

**E7. should-fix. NFR-30 states a permission result nobody measured.** **[searched]** `NSMetadataQueryUserHomeScope` is a documented scope and the page does not mention a permission. **[searched]** A 2026 Stack Overflow thread has one non-sandboxed app needing Full Disk Access before `NSMetadataQuery` returned `~/Documents`, and another developer saying sandboxed queries work better and FDA is a red herring. NFR-30's "file-name search works with every optional permission denied" and NFR-31's "Never requested: Full Disk Access" treat the optimistic answer as a fact. Round-1 Grok's "mdfind returns what Spotlight can already show" is the same overclaim.

**E8. should-fix. The Raycast memory figures are real and already marked provisional by their authors.** **[searched]** The 2026-05-14 Raycast post does say v2 is about 350–450 MB in use, the Swift shell about 40 MB, WebContent about 120–200 MB, Node about 150–200 MB, and it says those numbers are not final. §1 and the refused-list row quote them as the standing cost. Round-1 Grok also reported a 2.6 host-memory cut; that changelog was not re-opened today, so the draft should at least carry the post's own "not final".

### Checked, and not wrong

**[searched]** Rust 1.100.0 exists (released 2026-11-12). objc2 0.6.5 (2026-10-05). global-hotkey 0.10.0 (2026-11-09); changelog confirms exclusive registration. nucleo-matcher 0.3.1 is MPL-2.0 (2024-02-20). frizbee 0.13.0 and neo_frizbee 0.13.3 are both MIT (2026-08-13 and 2026-09-21). rusqlite 0.43.0 is MIT (2026-11-15) and bundles SQLite 3.54.1. numbat 1.24.0 is MIT/Apache-2.0 (2026-08-23), MSRV 1.88; the aarch64-apple-darwin CLI archive is 2.44 MB compressed; lib.rs lists about 13–20 MB of dependency source. Sparkle 2.10.1 (2026-10-25) is the latest stable; 2.11.0-beta.1 (2026-11-16) is a beta. Official `gpui` on crates.io is still 0.2.2 (2025-10-22); `gpui-unofficial` 1.29.3 was published 2026-11-20. The "licence to be confirmed" cell can be closed: link `neo_frizbee` 0.13.3, MIT, and do not also link `frizbee`.

**[searched]** A nonactivating `NSPanel` is documented, including by a March 2025 AppKit write-up, as able to take key events without activating the app, provided it is a panel, `canBecomeKey` is true and `canBecomeMain` is false. A borderless panel does not become key unless that override exists; a November 2026 Electron sample does exactly that override. I did not find a source that says Japanese or Chinese composition works in that configuration. **[searched]** A May 2026 report (Cherry Studio) has the system Chinese candidate window missing when a panel is shown over a fullscreen Space, while a third-party IME still shows. FR-7 is a hope. S4 can pass it on an ordinary Space and miss the case FR-3 actually creates.

**[searched]** Carbon `RegisterEventHotKey` needs no Accessibility permission. In September 2024 Apple required a modifier other than Shift or Option (`eventInternalErr` / -9868). In November 2024 an Apple engineer said 15.2 Beta 2 restored Option-only and Option-Shift. Nothing found today shows that restoration still holds on macOS 26 or 27. A October 2026 Go wrapper verified Option+Command chords on macOS 26.6.2, not Option alone. The `v0.10.0` macOS source path 404s, the same miss as round 1, so this review does not claim to have read the Carbon call. FR-1's "Carbon, no Accessibility prompt" is fair for an ordinary chord. FR-1's default of Option-Space is not established.

**Numbat vs the budgets.** Nothing published gives `Context` startup or RSS. The compressed CLI size does not threaten NFR-8 by itself. The prelude is a large included program (the unit system is Numbat code). D10's "measure in M1" does not make the cost compatible with NFR-5 or NFR-6; it postpones finding out until those gates are supposed to be green. No spike builds it.

## 2. Decisions

Agree, and the recorded dissent handling is fine: **D2** (macOS only, portability in `core`), **D6** (one resident process, scripts as the only children, CLI as a subcommand), **D8** (Developer ID, hardened runtime, notarised DMG, Sparkle 2, not the store), **D9** (no telemetry, no account, no sync). Sparkle 2.10.1 checks out. D6 still needs a single-instance rule that is not in the decision; that is a missing requirement, not a vote against D6.

**D1. should-fix.** I would decide AppKit through `objc2`, escape hatch a thin Swift shell, GPUI not on the list. Idle memory is why GPUI was withdrawn; it cannot be the thing you pick up when a budget fails. Evidence that would change my mind: the same panel spike fails in a Swift shell for a reason that is not "the bindings are awkward", or a hidden GPUI window on this Mac stays under 40 MB with no display link. The current text does not settle Claude's dissent. It restates it.

**D3. should-fix.** I would still query Spotlight and still refuse an indexer. I would not close "no Full Disk Access" until a signed build on macOS 27 answers E7, and I would not use two different thresholds. D3 reopens the indexer at about 150 ms. NFR-4 allows 200 ms. A file search can pass the gate and trip the revisit. Evidence that would change the permission half: that signed build returns names under Desktop, Documents and Downloads with every TCC grant denied. Evidence that would change the indexer half: capped queries (below) still miss a useful file at a p95 over 150 ms.

**D4. should-fix the record, not the outcome.** I would keep trusted local scripts, JSON on stdio, no Node, no dylibs, no Raycast API, WASM only after two real extensions need a sandbox. "Unanimous" is false. Astra's v1 included a long-lived JSON-RPC session and list/detail views; Grok deferred that until scripts felt cramped. "Ship the view protocol only if M2's scripts are cramped" is the right settlement, and it should be written as a dissent, not as agreement. Evidence that would pull EX-10 forward: two of the author's own scripts blocked on a form during the five-day test.

**D5. should-fix the spike, keep the policy.** Nucleo as the strict ranker, `neo_frizbee` only when the strict pass has fewer than three hits and the query has at least four characters. S3's rule, "whichever has the better top-1", will crown frizbee if the labelled set contains typos and crown nucleo if it does not, and it does not test FR-11's tier order at all. Pre-register two scores: strict queries (exact, prefix, acronym) and typo queries. The second pass is allowed to win only the second score. Evidence that would make frizbee the primary ranker: it beats the tiered nucleo order by a margin you would notice on strict queries, on this Mac, not the upstream Ryzen "about 4×" number. Both crates are MIT as of today, so the licence is no longer the open question. MPL-2.0 on nucleo is fine unmodified; the notice obligation should be one line in the licence note, not a reason to avoid it.

**D7. must-fix.** I would decide two files, as the plan already drew: one WAL database for catalog, usage, aliases and snippets, and a second for clipboard payload so purge and FTS stay off the ranking connection. Evidence that would put them back in one file: the second connection shows up in NFR-7's idle wakeups and a single file does not. Until then the decision table should match the diagram.

**D10. must-fix the timing.** I would ship `evalexpr` plus a small unit table for the daily driver, and leave Numbat behind the trait only after an M0 measurement: context construction, RSS delta, and a confirmation it does not touch the network. "Measure in M1 and fall back" means the fallback happens after the milestone that is supposed to be green. The 2.44 MB compressed CLI does not prove the embedded prelude is cheap; there is no published startup or RSS figure. Evidence that would put Numbat in M1: context init well inside the keystroke budget (a few milliseconds, not a frame), RSS delta under about 8 MB, binary growth that still leaves NFR-8 intact, and no currency fetch.

**D11. must-fix.** I would opt in during onboarding, store text only in M1, default to session-only, and make 7-day persistence a second explicit switch. Images stay M2. S7 stays the gate for whether concealed and transient markers are even visible. The draft's settlement text and Q8 cannot both be true. Evidence that would restore persistent-by-default: S0 shows clipboard recall is a daily action and S7 shows the password-manager markers are filterable on macOS 27. Placement inside M1 is then justified. The privacy default is still session-only until that evidence exists.

## 3. Requirements

**R1. must-fix. Q1 does not decide M1, despite claiming to.** Q1 says the top-30 recording decides M1's contents. The M1 scope line then freezes FR-1–FR-15, FR-17, FR-20–FR-27, FR-40, FR-41, FR-50 and FR-54. An author whose week is "launch, a script, a file" still has to build clipboard, snippets, emoji and Numbat before the five-day test, and does not get the script or the file.

**R2. must-fix. Several budgets are not decidable as written.**

- NFR-5 has no percentile, and it does not exclude the first launch after download. Gatekeeper assessment on a notarised app can be seconds. Astra's split (p95 with a saved catalog, first-run reported separately) is the testable form. Use p95 ≤ 400 ms on a warm signed launch; do not let the first Gatekeeper run fail the gate.
- NFR-6 is defined with clipboard history off. M1's exit requires every §6.1 budget green with clipboard history on. The same number cannot gate both configurations. Empty-panel hard gate should be ≤ 40 MB physical footprint. The 80 MB stop line is about twice the "tenth of Raycast" promise (a tenth of the cited ~400 MB is ~40 MB; the 50 MB target is the honest one). An empty panel at 70 MB passes NFR-6 and the stack is already wrong.
- NFR-1's p99 ≤ 40 ms has no measurement behind it (the cited tails are 15-sample vendor numbers). Keep p50 ≤ 16 ms. Loosen p95 to ≤ 33 ms until this Mac has 1,000 real summons. Do not block a milestone on an invented p99.
- NFR-9, "≥ 90% top-1 after one week of use", scores frecency's memory of that same week. Freeze the 100 queries before the week. Report cold top-1 separately, and expect something closer to 70% there. The 98% top-3 figure is only meaningful on that frozen set.
- NFR-7's "no periodic timer other than the clipboard poll" forbids a retention sweep and Sparkle's own schedule. Name the allowed timers.

**R3. must-fix. FR-11 and D5 are two rankers.** FR-11 is an ordered tier list (alias, exact title, prefix and acronym, then fuzzy) with frecency inside a tier. D5 says nucleo is the primary ranker. Nucleo's own score already mixes boundary and acronym bonuses into one number, which will cross FR-11's tier boundaries. Pick one authority. The tiers should win; nucleo scores only inside the fuzzy tier. FR-12 is also untestable: the two reports give different decay formulas (multiplicative decay of a counter versus `ln(1+uses) * exp(-age/14)`), and the draft copies neither. Write the formula down or the golden tests in S3 have nothing to lock.

**R4. should-fix. FR-10's M1 row depends on M2 providers, and it drops the providers that are actually slow.** Files and scripts are M2, but FR-10 is M1 and describes them appending. Calculator (FR-22, off the main thread, so late by design) and clipboard FTS are not classified as local or slow. A late calculator row is exactly the FR-14 race. Either calculator is local and bounded to well under 4 ms, or it appends into a reserved row and must not move a selection.

**R5. should-fix. Holes that will be discovered in implementation.**

- No single-instance rule, no stale-socket recovery. D6 says one resident process and does not say what the second launch does. Astra wrote this down; the draft dropped it.
- FR-8 offers Settings in M1. FR-51's settings window is M2. The status item item has nowhere to go.
- NFR-30 lists quicklinks among the things that work with the network off. Opening the URL is the feature. Say "the row is built and the URL is handed off" or drop quicklinks from that sentence.
- FR-5's click outside a nonactivating panel is not in S1. A global mouse monitor is the usual implementation and is not covered by "the hotkey needs no Accessibility permission".
- S1's matrix omits Stage Manager. Apple's mutual-exclusion rule for collection behavior exists specifically for Stage Manager and fullscreen.
- NFR-50 sets a macOS 14 deployment target and names tests only on 26 and 27. A floor you do not boot is not a floor. Astra's dissent (first release on the OS you have) is unrecorded.

**What moves.** Into M1, before the five-day exit: one script mode, `silent` plus `list` (EX-1, EX-2, EX-4's "nothing runs on summon"), because G1 allows scripts and the switch story in both reports includes one personal command. Out of M1 unless S0's top 30 says otherwise: snippets (FR-26) and the persistent clipboard default. Emoji, quicklinks and system commands are small enough to stay. File names stay M2 only if the top 30 agrees; do not freeze that either way in the scope line.

## 4. Plan

**P1. must-fix. S1 and NFR-2 can pass without a hotkey or a focus handoff.** §4 synthesises the hotkey and requires the sentinel to appear in the field. A handler that writes the sentinel into the field on the hotkey callback passes, including when RegisterEventHotKey returned -9868 for Option-Space and when the same character also landed in Terminal. The 1,000-summon bar is in S1 (days 1–3) and the harness that could run it is S2. Pass condition that would mean something: Option-Space returns `noErr` on this macOS 27; the sentinel arrives as an event; the previous app's document does not contain it; the count is 1,000 only after S2 exists. Manual matrix stays in days 1–3.

**P2. must-fix. S4 has no tradeoff and does not test the failure that has actually been reported.** The pass line is composition in the S1 binary, not composition over a fullscreen Space (E6, the Cherry Studio case). The failure instruction is "investigate to the bottom, not a workaround." If the system IME cannot anchor a candidate window to a nonactivating panel over fullscreen, a Swift shell will not fix it, and there is no rule for whether FR-3 or FR-7 yields. Timebox S4 to a few days. If system Pinyin or Kotoeri cannot confirm a composition over a fullscreen Space without an activation, ship with an explicit limit (candidate window fails over fullscreen, or the panel activates only while marked text exists) and write it into FR-7. Do not hold M1 open for a WindowServer bug.

**P3. must-fix. File search is specified so that it misses its own gate.** **[searched]** `NSMetadataQuery`'s default notification batching interval is 1.0 second, which is already five times NFR-4. The class has no public max-count; short queries of a home directory are a known multi-second, hundred-thousand-row gather, while the C API's `MDQuerySetMaxCount` is how launchers stay fast. The plan says "batched" and never sets the interval or the cap. Add both to FR-30: batching interval well under the gate (50 ms is the right magnitude), hard cap around 50 rows, no Spotlight query below two characters. Put a half-day probe in M0, not M2: signed app, TCC denied, 1- and 3-character names, first batch time, whether Documents comes back. D3 is an architecture decision. Finding out in week 7 is how an indexer sneaks in "just for now".

**P4. should-fix. Schedule for one developer with agents.** Weeks 3–6 as written are app discovery, frecency, aliases, TOML, Numbat, quicklinks, system commands, emoji, snippets, clipboard with the NFR-32 rules, Command-K, status item, login item, appearance, a notarised DMG, and five clean dogfood days. Astra's weeks 3–6 were a smaller slice and already included files and scripts. Agents do not shorten focus bugs, notarisation, or the five days. As written, M1 is six to eight weeks before the test starts, and M3's "three outsiders plus a VoiceOver user plus a Sparkle update" has no recruiting step anywhere in weeks 1–10. Cut M1 as in R5, start asking those four people during M1, and treat 14–16 weeks as the engineering envelope only after that cut. The VoiceOver exit with no participant is a gate that cannot be passed and cannot be failed.

**P5. should-fix. Other exit criteria that pass while the thing is still broken.**

- S3 accepts "the matcher with the better top-1" with no split between strict and typo queries (D5) and no assertion of FR-11's tier order. Two bad matchers still produce a winner.
- M2's "27 of the top 30" is gameable if S0 is written to fit the product, and impossible if S0 includes a refused feature (AI chat, tiling, browser tabs) with no rule to exclude it. Define the denominator as in-scope actions before the test.
- M0 exit does not include S5–S7, which is right, but it then closes the stack for a year. Close the windowing stack. Do not close the matcher, the calculator, or the licence in the same sentence if those spikes have not run.
- S7 failing moves clipboard to M2, while the M1 scope line still lists FR-27. One of those has to be the scope.

**Biggest practical failure.** The five-day switch is at the end of a milestone that builds the wrong half of the habit, scored by a harness that can go green without Option-Space registering and without IME working over fullscreen. Risk 5 ("the author does not switch") is listed as if it were a motivation problem. The schedule causes it. S4 then has no timebox, so the alternative failure is the same milestone never opening because a candidate window is a WindowServer bug.
